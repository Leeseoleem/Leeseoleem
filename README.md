## About

화면을 볼 때부터 코드 구조를 함께 연결해 사고합니다. 화면과 구조를 따로 해석하는 과정이 줄어들기 때문에, 수정이나 기능 확장이 필요할 때도 흐름이 끊기지 않는 구조를 설계할 수 있습니다.

기획과 UX 설계 단계부터 참여하고, 프론트엔드 구현과 스토어·플랫폼 출시, 출시 이후 운영까지 직접 맡아왔습니다.

- Google Play 1건, 앱인토스 2건, 총 3개 채널에 정식 출시
- 가라챠토는 매일 도는 크론 파이프라인으로 무인 운영 중
- 2024년 6월부터 Velog에 트러블슈팅과 학습 과정을 기록

## 설계 · 협업 방식

프로젝트마다 반복해서 적용한 방식입니다.

| 영역 | 내용 | 적용 |
| --- | --- | --- |
| **헤더 렌더링** | 헤더 타입 5종을 discriminated union config로 정의하고 렌더링 책임을 Layout으로 이관, 페이지는 config로 의도만 선언 | 핏플 |
| **DB 스키마** | 곡 메타, 노래방 수록 정보, 차트 이력을 3계층으로 분리해 곡당 AI 번역 호출을 1회로 제한 | 가라챠토 |
| **데이터 검증** | 규모가 커지며 깨진 전제를 기준 함수와 검증 쿼리로 명시화해 재발을 상시 감지 | 가라챠토 |
| **테마 시스템** | 포인트 4색 × 3단계 디자인 토큰, 하드코딩 색상 금지 규칙으로 theme 단위 관리 | 우리두, 생일 카드 |
| **컴포넌트 문서화** | Storybook과 갤러리 화면으로 공통 컴포넌트 재사용 기준 관리 | 핏플, 생일 카드, 우리두 |
| **협업 규칙** | 커밋·브랜치 컨벤션과 WebView 연동 명세(RN_BRIDGE)를 README에 문서화해 웹·앱 레포 공통 기준으로 운영 | 핏플 |
